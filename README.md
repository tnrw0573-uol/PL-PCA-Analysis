# PCA-Analysis
## Context
In my first year of university, I studied Principal Component Analysis (PCA), which transforms high dimensional data into a lower dimensional space, while retaining as much information as possible without losing its relationships and patterns.  In this project, I take a dataset of every player in the Big 5 European Leagues (Premier League, La Liga, Ligue 1, Bundesliga and Serie A), apply PCA and see which players the analysis thinks have a similar playing style.  I decided to do this project as a way for me to apply what I learnt about PCA on a real dataset, and I chose a footballer dataset as I am very interested in football and I'm curious to see how football clubs decide to recruit, particularly for a player's replacement. 

## Data
All the data I used was from TheStatsAPI. This API covers all Big 5 leagues extensively and has an endpoint that allows access to a player's stats for a specific competition and season. The analysis is on the current season as long as it is roughly halfway done, otherwise it is on the last full season. As this is September 2026 currently, the analysis will be on the 25/26 season. For my analysis, I omitted the stats which don't define playstyle, such as disciplinary stats (yellow cards, red cards, penalties won/conceded), alongside own/opposition half passes. Furthermore, stats which are highly correlated with other stats (total shots, shots off target, total duels won, accurate/inaccurate passes) were also left out. Lastly, all stats were transformed into per-90 stats so that players aren't matched together because they have played a similar amount of games, which again isn't relevant to playstyle.

An issue I came across while fetching the data was that some stats were left as null, specifically "aerial duel win percentage" and "successful dribbles percentage" for every player except for goalkeepers, for whom they were set to 0. Seeing that those stats were not null for a player for previous seasons, I assumed that this was because they were simply not available yet. Therefore, I chose to drop these stats from the analysis altogether, which should not dramatically affect the results as there are 15 other stats I used.

## Methodology
To compare a player against other players, I first needed to fetch every player's stats for the 25/26 season and store them in order to work with them, this is what fetchdata.py does. It finds each league's id, the 25/26 season's id unique to each league and the id of every team that participated in it. From the id of the teams I can find every player's id and using a player's id and season id I can access a player's statistics. After getting a player's statistics, I choose the stats that are relevant and convert them to per-90 stats, repeating this for each player from every team until I have a complete dataset. From this point I chose to apply PCA in two different ways: generating two dimensional scatter plots and creating a Streamlit app which calculates a player's most similar counterparts in playstyle.

### PCA Plots
The first way I applied PCA was through generating two dimensional scatter plots; two dimensional scatter plots are easy and straightforward for the user to understand. The user can choose between seeing scatter plots for all players, or players of a specific position (goalkeepers, defenders, midfielders, forwards). Depending on what the user chooses, the dataset is filtered by position, standardized and reduced to two principal components. Standardizing the data (making each statistic have mean 0 and standard deviation 1) is particularly important since PCA looks at which direction has the maximum variance and this will be disproportionately influenced by statistics which have a larger numerical scale. Once that is done, the user is shown the plot. If the user chose to run an analysis on all players, the points representing each player are coloured by position, otherwise the points are in one colour. Lastly, hovering over a point on the plots will show the user the player it represents.

### Player Similarity Finder
The other way I applied PCA was through finding a given player's 10 closest matches in playstyle. The user enters the player they want and chooses to compare the player to those with the same position or all. Using the player's name given by the user, I fetch the player's ID and find the player's stats for last season by searching through each league's relevant season. The dataset is then reduced; if the user chose to find players within the same position the dataset is filtered by that position before being reduced. Instead of it being reduced to 2 principal components like in the plots, the dataset is now reduced to however many principal components that, when accumulated, explain 95% of the variance since the user isn't being shown plots which need to be visually comprehensible. 

The player's stats are then standardized and reduced using the same scaler and PCA transformation fitted on the dataset. Now that I have the player's row reduced, I calculate the cosine distance between the player and the others. Between cosine and euclidean distance, I believe cosine is the best measure for the similarity finder because cosine distance looks at the similarity of the ratio of the players' stats, whereas euclidean looks at how similar those players are by the stats' values. To give an example, two players that both make twice as many key passes as tackles could be considered creative players and be closer in cosine distance, whereas this might not be the case under euclidean distance as it depends on if they make similar amounts key passes and tackles. Once each player's distance is calculated, it is added to the dataset as a new column. Lastly, we sort players by their distance in ascending order, take the first 10 players and display them to the user.

## Limitations 
One of the most significant limitations on this project was that the API didn't directly provide a player's historical stats for the seasons prior to the one being analysed on currently. I could have improvised by searching through each match the player has played in and collecting their stats, however this risked going over the API's rate limit. Another issue with the API I used was some useful and informative stats weren't available, such as expected goals (xG), expected assists (xA). Progressive passes and carries would have been particularly useful for analysing and differentiating between midfielders who are tasked with getting the ball into dangerous aread and midifielders who are "safer" with it. What I believe is the most significant limitation is the lack of goalkeeper specific stats such as save percentage, xG conceded, post shot xG faced and defensive actions outside the penalty area. This would have made the difference in style between each goalkeeper noticeable (aggressive vs passive goalkeepers) and this is the reason why I omitted the analysis on goalkeepers in my evaluation of the plots and finder.

## Conclusion
Overall, the project demonstrated how PCA can be used to find players who are similar in their playing style. From a broader point of view, such as the plots, positional patterns were visible, while as the same time, players with the same position had very different profiles. Furthermore, it showed me that some players could have such unique profiles that they appear similar to players of other positions (like the attacking full backs mentioned in the plots' evaluations). The finder was made to be more accurate in finding similar profiles, which it accomplished, however faced diffculty doing so for wing-backs perhaps due to their particular role in a team. If I was to revisit this project in the future, I would try to find an API which would cover a bigger range of statistics, especially goalkeeper statistics, to make the analysis to distinguish between players more extensively.
